# 杠杆 ETF 阶梯加仓:回测与当前仓位

纯静态网页(无后端、无依赖):左侧调参数,右侧看回测结果、当前仓位与下一档建议。

作者:[@ycj28c](https://github.com/ycj28c)

> **免责声明**:仅为个人研究/学习工具,**不构成投资建议**。合成数据(1999 起)偏乐观;未计税、滑点、融资利差差异、做空/借券限制等;杠杆 ETF(如 TQQQ)可能出现 −99% 左右的回撤。历史不代表未来。

## 页面功能

- **左侧参数面板**(修改后自动重算):数据模式(合成 1999 起 / 真实 ETF 2016 起)、起始日期与资金、底仓标的(VOO/SPMO/QQQ)、现金年化(真实模式,默认 0.02 即 2%)、平常仓位、五档阶梯、TQQQ 上限、外部资金。
- **回测**:概览指标卡与对比表(阶梯策略 vs 持有 QQQ / QLD / 底仓)、资产曲线与回撤、按年度收益、回撤 ≥20% 区间、操作日志(含每次操作后的各项持仓与总值)、滚动 5 年窗口分布(展开时自动计算)。各部分可折叠。
- **当前仓位与建议**:以最近一次前高为起点推演到最新一天,显示回撤、已触发档数、回补线、各档触发价、QQQ 近 252 日年化波动、按 K 算出的动态上限、下一档的买卖金额;可输入假设 QQQ 价格(如盘中价)和你的实际持仓做对比。
- **规则说明**:页内有策略的简要解释与默认阶梯表。

## 策略规则

- 信号:QQQ 收盘价相对**冻结前高**的回撤(进入加仓状态后前高不更新)。
- 平常仓位默认:TQQQ 0 / 底仓(VOO 或 SPY)70 / QLD 15 / 现金 15。
- 阶梯(默认):−10% 卖底仓 1/10;−15% 底仓 1/4 + 现金 1/4;−20% 各 1/3;−25% 各 1/2;−30% 全部;均买入 TQQQ。比例是剩余持仓的比例。
- TQQQ 上限只在**买入时**检查(上限 × 总资产 − 现有 TQQQ),上涨后超过上限不强制卖出。上限可为固定比例,或每年初按 `K ÷ 过去 252 日 QQQ 波动率` 计算(夹在上下限之间)。
- 回补:QQQ ≥ 前高 + (前高 − 谷底) 时,恢复平常仓位,TQQQ 清零,前高解冻。
- **回补与 TQQQ 减仓**(三项相互独立):
  - 回补(默认开启):QQQ 从底部涨一个跌幅(≥ 前高 + (前高 − 谷底))时恢复平常仓位。关闭后不整体回补,QQQ 创新高时只重置前高与档位,持仓保留。
  - QQQ 回到前高 → 卖出设定比例的 TQQQ 换成 QQQ(默认关闭)。
  - TQQQ 自本轮低点上涨 N% 时减仓:规则列表,可添加多条,每条设置涨幅、卖出 TQQQ 的比例、所得换现金的比例(其余换 QQQ)。
  - 每条规则每轮最多触发一次,减仓后不会重新买回 TQQQ;QQQ 作为单独持仓记录。
- **外部资金**(可选,默认关闭):回撤超过 −35% 后,底仓和现金已基本用完,改由组合之外的新增现金继续加仓。默认触发回撤 `35,40,45,50,55,60,65,70,75,80,85`(%),每个阈值每轮只触发一次,每笔为起始资金的 10%(共 11 笔 = 110%)。收益用时间加权(TWR)与 IRR 报告。
  - 买入标的可选"底仓"(默认)或"TQQQ"。
  - 买 TQQQ 时可选**是否受 TQQQ 上限约束**:受约束时,TQQQ 买到上限为止(上限 × 加入新资金后的总资产 − 现有 TQQQ),**超出部分买底仓**,每笔都全额投出,不放现金;TQQQ 已超上限则整笔买底仓,不会卖出已有 TQQQ。不受约束则整笔买 TQQQ。

## 数据与假设

- `data/prices.json`:QQQ、SPY、VOO、SPMO、QLD、TQQQ 的复权收盘价 + `^IRX`(13 周国债收益率),来自 Yahoo Finance 的**非官方**图表接口。
- 合成模式:TQQQ = 3×QQQ 日收益 − 2×国债日利率 − 年费 0.95%/252;QLD = 2× − 1×;底仓 = SPY;现金 = 13 周国债。底仓标的选 QQQ 则底仓用 QQQ 本身,选 VOO/SPMO 则用 SPY 代替;此模式下"现金年化"不生效。
- 真实模式:用真实 ETF 价格,现金按"现金年化"计息(默认 2%);"合成年费率"不生效。
- 回测按**收盘价**触发,前高也取收盘价最高(例如 2026-10-06 QQQ 收盘 759.66,盘中最高 762.86)。实盘若按盘中价操作,触发价会略有不同。
- **边界敏感**:回撤恰好卡在档位边缘时,复权价 ~1e-6 的噪声就可能让触发日改变(例如 2000-04-11 的 −15%),最终值可相差约 3%。不要拿不同次抓取的数据互相比较。
- 外部资金只有在回撤达到阈值时才触发。2016 年起的真实区间 QQQ 最大回撤约 35%,几乎不触发;1999 起的合成区间会触发。

### 数据再分发注意

Yahoo 数据的服务条款可能不允许再分发。公开仓库前请自行确认;如有顾虑,可把 `data/prices.json` 加入 `.gitignore`,改为在 Actions 里构建时抓取并只部署到 Pages(仍属公开发布,需自行判断),或改用你有授权的数据源。

## 本地使用

```bash
python3 -I scripts/fetch_data.py        # 更新数据(标准库,无需 pip)
python3 -m http.server 8000             # 在项目根目录运行
# 打开 http://localhost:8000/web/
```

不能直接双击 html(浏览器会拦截 fetch 本地 json);必须在含 `web/` 和 `data/` 的根目录启动服务。

## 测试

```bash
node tests/engine.test.js               # JS 引擎 vs 独立 Python 实现(同一份数据)
python3 -I tests/reference.py           # 数据更新后重新生成 tests/reference.json
```

每次更新数据后,合成用例的参考值可能因复权价噪声而变化,需重新运行 `reference.py`;因此测试**不放进**自动部署流程。

`tests/engine.test.js` 里的"真实 ETF"用例固定结束日 2026-11-17,不受之后数据更新影响;合成用例对照 `reference.json`。

## 部署到 GitHub Pages

1. 新建公开仓库,把本目录内容(**包括隐藏目录 `.github`**)放进去并推送。网页拖拽上传常会漏掉 `.github`,建议用 `git push`;macOS 访达按 `Cmd + Shift + .` 可显示隐藏文件。
2. Settings → Pages → Source 选 **GitHub Actions**(不要选 Jekyll 或 Static HTML 模板)。
3. `.github/workflows/pages.yml` 会把 `web/` 和 `data/prices.json` 拼成站点并发布(`build` 与 `deploy` 两个 job,缺一不可)。首次推送时若 Pages 还没开启会失败,开启后到 Actions 页手动 Run workflow。
4. `update-data.yml` 每个工作日抓取一次数据并提交,需要:Settings → Actions → General → Workflow permissions 选 **Read and write permissions**。
5. 站点地址:`https://<用户名>.github.io/<仓库名>/`。更新后浏览器用 `Cmd + Shift + R` 强制刷新。
